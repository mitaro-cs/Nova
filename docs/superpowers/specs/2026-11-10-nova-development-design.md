# Развитие Nova - предварительная спецификация

Статус: предварительная. Основана на статическом обзоре; воспроизведение, измерения и проверка макетов ещё необходимы.

## Цели и ограничения

Сохранить существующие данные, интерфейс каталога и движок воспроизведения. Сначала установить исходные показатели и проверить безопасность; после этого менять аккаунт, настройки и источники. Схема меняется только новыми миграциями. Сессии хоста на отдельном порту, ограничения внешних запросов и совместимость Safari/Windows обязательны.

## Аккаунт и управление

В профиле объединить изменение имени и логина с проверкой уникальности на сервере; первый пароль хоста задавать через доверенный локальный сеанс. Существующий пароль менять с проверкой текущего и отзывом других сессий. Отдельно проверить поведение открытых чатов и повторный вход.

Настройки сгруппировать по назначению, снабдить поиском, описаниями, текущими и стандартными значениями. Опасные операции подтверждать существующим диалогом. Для каждой настройки сначала установить действующего владельца, реальные значения по умолчанию и допустимость удалённого изменения; не создавать декоративные переключатели без серверной реализации.

## Источники и плеер

Для каждого каталога хранить включение, порядок, шаблон поиска и диагностический статус. Определение типа источника - предварительная оценка, которую хост может исправить. Ошибка отдельного сайта не должна блокировать остальные. Существующие ограничения URL и проверку публичного DNS сохранить для всех переходов и медиасегментов.

Озвучки, субтитры и качество показывать только если источник действительно их предоставляет и сервер может безопасно передать их существующему движку. Ошибка или антибот - честный статус недоступности. Проверка страниц сторонним инструментом не доказывает воспроизведение: необходимы реальные проверки из сети хоста.

## Приватность и поиск

Проверять права на стороне сервера для каждого маршрута сообщений, комнат и приватных разделов. Экспорт и удаление должны учитывать связанные данные, архивы и роль хоста; предусмотреть невозможность оставить установку без администратора. Поиск должен объединять нормализацию раскладки, транслитерацию и ограниченное нечёткое сравнение без сетевых запросов на каждое нажатие.

## Устройства и визуальный стиль

На телефоне использовать нижнюю панель с безопасными отступами; на ПК - закреплённую карточку профиля и содержимое справа; на ТВ - крупный фокус и управление пультом с совместимостью Chrome 69. По присланному референсу профиль строится вокруг затемнённой стены постеров, круглого портрета, имени и текущего просмотра; ниже - показатели, медали, жанры, счётчики и действия. Белый акцент и неподвижный ободок аватара обязательны. Текущая ProfileCard уже содержит значительную часть этих элементов; различия проверять по реальным снимкам.

Референс плеера: изображение занимает почти всю поверхность, управление поверх плавно затемнённого нижнего края, тонкая шкала, центральная кнопка воспроизведения и симметричные перемотки, вторичные настройки и полноэкранный режим по краям. Существующие команды, доступность клавиатуры и мобильные жесты сохранить; на ТВ отдельно обеспечить видимый фокус. Отображать только действия, которые действительно поддерживаются.

## Проверка

Перед реализацией подготовить HTML-макеты и снимки целевых размеров, измерить фактические LCP, INP, CLS и размер JS. Для каждого этапа запускать соответствующие серверные, браузерные и медийные проверки. Успех проверки на настоящем телевизоре фиксировать только после фактического запуска на устройстве.
