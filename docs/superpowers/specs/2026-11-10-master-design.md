## 1. Баг профиля: имя, логин, пароль

Факты аудита (проверено запуском): `PATCH /api/me` (имя) и `PUT /api/me/password`
(включая первый пароль у хоста без пароля) **работают** для любой роли и через оба
порта. Логин не меняется нигде - в `MeBody` нет поля, UI показывает только `@login`.
`Security.svelte` скрыт при `!hasPassword`, хотя `/api/me/security` отвечает 200.

Решение:
- `PATCH /api/me` принимает `login`: проверка `auth::check_login`, уникальность
  (`COLLATE NOCASE`, как у входа), регистр хранится как введён (lowercase, как при
  создании). Ответ обновляет `me.user.login`; чаты/комнаты читают имя профиля из БД
  на каждое сообщение - обновление мгновенное. Своя локальная сессия окна хоста
  (`login='host'`) может сменить логин на любой свободный; вход по старому логину
  после смены невозможен (логин - часть credentials).
- UI `/profile`, вкладка «Аккаунт и безопасность»: три формы - «Имя», «Логин»,
  «Пароль». У логина - подсказка «по нему вы входите с других устройств»; при смене
  показываем новый логин. Подтверждение опасных действий - через `dialogs.svelte.ts`.
- `Security.svelte` рендерится **всегда** (убрать `{#if me.hasPassword}`): TOTP и
  журнал входов доступны и без пароля. Внутри `Security` уже есть ветки для
  `!hasPassword` - проверить и дописать тексты.
- Правила `docs/host-password-reset.md` сохраняются: удалённо пароль хоста через
  admin API не меняется; свой пароль хост меняет через `/api/me/password` как все.
- Тесты: `server/tests/security.rs` - смена логина (уникальность, вход по новому,
  старый отклонён, регистр), первый пароль у хоста, видимость security-эндпоинтов;
  e2e `profile.spec.ts` - формы.

## 2. Настройки хоста: единый раздел

Сейчас «Управление» - 15 разрозненных компонентов + ключи в `settings`, часть без UI
(`media.trickplay`, `discover.feeds`, `names.wikidata.sparql`, `ruwiki.tried`,
`api.nextembed.ws`).

Решение - один раздел «Настройки» с:
- **Поиском** по названию и ключу настройки (клиентский фильтр по манифесту).
- **Группами** (маппинг существующих компонентов, ничего не переписываем с нуля):
  1. Профиль и безопасность - сайт (имя, язык описаний), удалённое управление, журнал входов;
  2. Доступ из интернета - `access.*` (cloudpub/fxtunnel/custom/lan), регистрация;
  3. Папки и добавление - `media.inbox`, `Inbox.svelte`, `Folders.svelte`, `Catalogs.svelte`;
  4. Источники - видео-поиск (VK token, свои сайты `video.sites`, источники онлайн - см. §3),
     метаданные (provider, ключи TMDB/KP, зеркала);
  5. Люди и роли - `People.svelte`, `Wishes.svelte`;
  6. Чат и комнаты - (новое, см. §4: опрос чата, голос, лимиты);
  7. Плеер по умолчанию - автозапуск, `media.trickplay`, качество по умолчанию;
  8. Оформление - `ThemeSettings.svelte`, `NightMode.svelte`, `theme.choice`;
  9. Уведомления и почта - `MailSettings.svelte`;
  10. Обновления и копии - `Version.svelte`, downloads, ffmpeg.
- У каждого пункта: **подсказка**, **значение по умолчанию**, кнопка **«Сбросить»**
  (возврат к дефолту из манифеста, только для переопределённых).
- Опасные действия (закрыть регистрацию, выключить удалённый доступ, удалить
  источник с видео у фильмов, сбросить ключи) - подтверждение через
  `dialogs.svelte.ts`, без `confirm()`.
- Манифест настроек - `web/src/lib/admin/manifest.ts`: `{ key, group, title, hint,
  kind: 'bool'|'text'|'secret'|'select', default, options? }`; серверный
  `GET /api/admin/settings` дополняется `defaults` и `overrides` (только
  отличающиеся от дефолта ключи), чтобы «Сбросить» знал, что чистить.
- Мгновенное применение там, где уже есть (`PUT /api/admin/settings` по одному
  ключу); группа «Чат и комнаты» - новые ключи `chat.poll_ms` (дефолт 3000),
  `chat.history` (дефолт 60), `room.idle_min` (дефолт 10) - с валидацией диапазонов.

## 3. Источники контента (онлайн добавляет только хост)

Текущее состояние (проверено кодом и живыми запросами): поиск видео
`video_search.rs` объединяет `rutube, vk, archive, peertube, commons, lordfilm,
own` (свои сайты `video.sites`, каталоги `video.catalogs` через `own_sites.rs`).
Всё через `outbound::valid_url`, кэш, семафор 4, лимиты.

### 3.1 Что показала разведка сайтов (проверено запросами)

Сайты владельца - клоны «лорфилм-движка» (DLE-подобные каталоги фильмов/сериалов
с внешними плеерами), но движки и плееры **разные**:

| Сайт | Тип | Что внутри |
|---|---|---|
| `the-bear-lordfilms.ru` | сериалы (многосерийник-каталог) | страницы `/film/<slug>-N-sezon-YYYY/`, iframe `api.namy.ws/embed/movie/{id}?season=N` и запасной `*.stloadi.live?token_*` |
| `mg.lordfilm.md/filmy/` | фильмы (каталог) | классический LordFilm DLE, плеер `api.nextembed.ws` |
| `lordserials.fan` | сериалы (каталог, WP) | `/film/…`, `/multserialy/…`, тот же класс плееров |
| `hd1.garri-potter-lordfilms.com` | франшиза | страница франшизы, iframe `*.newplayjj.com:9443/?token_*` |
| `serialfriends.org` | один сериал | **403 на прямой запрос** (антибот) - статус «нужна проверка», не блокирует остальные |
| `south-park.mult-fan.tv` | один сериал | страница-заглушка «Подтвердите, что вы человек» (JS-челлендж) - то же |

**Ключевой факт (проверено):** все проверенные плееры (`api.namy.ws`,
`api.nextembed.ws`) отдают в HTML встроенный JSON `seasons:[{season,episodes:[…]}]`,
и у каждой серии единая схема:

- `hls` - master.m3u8; `dash`/`dasha` - MPD (запас);
- `audio.names[]` + `audio.order[]` - **озвучки** («HDRezka Studio», «RuDub»,
  «DniproFilm (укр)», «Eng.Original»…);
- `cc[]` - **субтитры** `{url: *.vtt, name}` («Рус. полные», «Eng. SDH»);
- `duration`, `title`, `sections`, `preview`.

Внутри самого master.m3u8 - `EXT-X-MEDIA TYPE=AUDIO` на каждую озвучку
(rus0..rus6, eng7) и `EXT-X-STREAM-INF` на качество (720p/360p…). То есть
hls.js уже умеет показывать озвучки и качество - нам нужно **дотянуть до плеера
VTT-субтитры** (`cc`) и человекочитаемые имена дорожек (`audio.names` →
соответствие индексам треков). DASH не используем (hls.js его не играет;
`hls` есть всегда).

### 3.2 Архитектура: адаптеры источников

Новый модуль `server/src/sources/` - реестр адаптеров. Контракт адаптера:

```
trait Source {
    id() -> &str;                    // "namy", "lordfilm-dle", "generic"…
    scope() -> Scope;                // Films | Series | Franchise | Any
    search_url(query) -> Url;        // шаблон поиска каталога
    parse_cards(html, base) -> Vec<Card>;   // карточки выдачи
    embeds(page_html, base) -> Vec<Url>;    // iframe плееров со страницы
    parse_playlist(html) -> Option<Playlist>; // seasons JSON → серии
}
```

`Playlist` - серии с полями `hls, audio_names, subtitles[{name,url}], duration`.
Адаптер **не знает про сеть** - сеть только через `outbound`/`stream_link::page`
(SSRF-защита, таймауты, лимиты сохраняются).

Адаптеры этапа 1:
- `namy` - семейство плееров namy.ws / nextembed.ws / stloadi / newplayjj и им
  подобных (все отдают один JSON `seasons:`) - **один универсальный парсер
  плейлиста**, различаются только правила поиска страниц;
- `lordfilm-dle` - LordFilm/DLE-клоны: поиск `index.php?do=search&story={q}`,
  карточки `th-in`, страницы `/filmy|/serialy/*.html`, iframe-детектор плеера;
  обобщение текущего `lordfilm.rs` с `HOST` → список хостов;
- `generic` - ручной источник: хост вводит домен + шаблон `{q}`; при «Проверить»
  сервер сам определяет тип (DLE-разметка? embed-плейлист?) и сохраняет
  распознанный адаптер; если не распознал - источник сохраняется со статусом
  «тип не определён», поиск по нему идёт только по прямым ссылкам на видео
  (старое поведение `own_sites`).

### 3.3 Шесть источников владельца - стартовый набор

Встроенные карточки (все **выключены по умолчанию** - включаются руками хоста,
т.к. это внешние сайты):

1. `the-bear` (series, namy) - the-bear-lordfilms.ru
2. `friends` (series, generic→autodetect) - serialfriends.org
3. `south-park` (series, generic) - south-park.mult-fan.tv
4. `mg-films` (films, lordfilm-dle) - mg.lordfilm.md
5. `lordserials` (series, lordfilm-dle/wp) - lordserials.fan
6. `hp` (franchise, generic) - hd1.garri-potter-lordfilms.com

Для single-title сайтов (friends, south-park, hp) источник = «этот сериал/
франшиза целиком»: поиск находит страницу серии, плеер даёт все серии.

### 3.4 Озвучки, качество, субтитры в нашем плеере

- Сервер при разрешении ссылки серии отдаёт в `stream`-ответе метаданные:
  `audio: [{index,name}]`, `subs: [{name,url}]`, `duration`.
- Фронт `stream_link`: master.m3u8 идёт через существующий прокси `p?u=`
  (hls.js видит все аудиодорожки и качества сам); VTT-субтитры проксируются
  тем же механизмом и подключаются `<track>`/hls.js subtitleTracks.
- Имена дорожек: `rus0..` в m3u8 → человекочитаемое имя из `audio.names`
  (соответствие по `order`); если имён нет - показываем как есть.
- Прокси `p?u=`: allowlist расширяется не «всем интернетом», а хостами,
  встреченными в ответе embed-страницы (page host + embed host + CDN host из
  подписанных URL). `outbound::valid_url` (публичные IP, DNS, лимиты) - без
  изменений; Referer при необходимости подставляем embed-хост.
- DASH игнорируем; если у эпизода нет `hls` - серия недоступна (статус в UI).

### 3.5 Реестр, здоровье, ручное добавление

- `settings video.sources` - JSON `{custom:[{id,url,scope,adapter,enabled,order}],
  order:[...], builtins:{id:{enabled,priority}}}`; встроенные по умолчанию
  выключены (кроме уже существующих rutube/vk/… - те остаются как сейчас).
- `video_health` расширяется: ключ = id адаптера/источника, статусы
  ok/down/unknown, «Проверить» в UI дёргает реальный запрос и обновляет.
- Антибот-сайты (403/JS-челлендж): адаптер отдаёт `unsupported`, источник
  помечается «недоступен с сервера», поиск его пропускает - без падений.
- Новый источник никогда не включается сам; порядок = приоритет в выдаче.
- `GET /api/admin/sources` + `POST /api/admin/sources/{id}/check` -
  состояние, последний ответ, ошибка человеческим языком.

### 3.6 Производительность и стабильность

- Плейлист embed-страницы кэшируется (TTL ~10 мин) по URL серии; повторный
  просмотр не ходит на сайт.
- Поиск по источнику - последовательно внутри адаптера, параллельно между
  источниками (существующий семафор), общий таймаут ~4 с на источник,
  `video_health` отключает источник после 3 сбоев на 10 мин.
- Парсинг - regex/serde_json по уже скачанной странице, без headless-браузера
  (нет JS-челленджей на стороне сервера; сайты с антиботом - «не поддерживается»).
- Никаких ffmpeg для внешних источников: только проксирование плейлистов/VTT.

## 4. Чаты и комнаты: изоляция

Проверено: `api/social.rs::friends_only` - переписка только друзьям (сервер);
комнаты в памяти, SSE, голос-сигнал только voice-участникам (тест есть);
история чата до 60 сообщений, комната закрывается через 10 мин.

Решение:
- **Оставить опрос 3 с для личных чатов** (стабильность > новизна; SSE-инфраструктура
  уже есть у комнат - миграция личных чатов на неё = риск без нужды). Добавить:
  - серверный `ORDER BY id` + `?after=` уже есть - проверить индексы;
  - тесты утечки: `server/tests/social.rs` - не-друг не читает/не пишет, история
    не утекает через `after=0`, комнаты - изоляция событий между room id.
- Доставка: порядок по `id`, дедуп на клиенте по id сообщения, реконнект с
  exponential backoff 1→3→10 с, индикатор «нет связи» в шапке чата.
- Новые настройки §2 группа «Чат и комнаты» (`chat.poll_ms`, `chat.history`,
  `room.idle_min`).

## 5. Безопасность и приватность

Проверено: CSP/заголовки в `web.rs` (nosniff, referrer same-origin, permissions-policy,
frame-ancestors none), CSRF `X-Fsfy`, Argon2id, сессии по SHA-256, ротация сессий при
смене пароля, журнал входов, лимиты, TOTP, `outbound` SSRF-фильтр, приватность
`vis_stats/vis_watched/vis_reviews/show_activity` в `api/profile.rs`.

Дыры/пробелы и решения:
- **Экспорт данных**: `GET /api/me/export` - JSON со профилем, прогрессом,
  `my_list`, оценками, отзывами, списками, друзьями (без чужих данных); кнопка
  «Скачать мои данные» в профиле.
- **Удаление аккаунта**: `DELETE /api/me` - для не-хоста: удаляет users+profile+
  все `profile_id`-данные (прогресс, списки, оценки, отзывы, друзья-заявки,
  сообщения); для хоста - только если существует второй host/admin, иначе 409
  «назначьте другого администратора». Подтверждение паролем + диалог.
- `accepts()` q=0 - см. 0.3.
- `script-src 'unsafe-inline'` - оставить (SvelteKit inline), зафиксировать
  комментарием; CSP не трогаем без нужды.
- Проверить и закрыть: email не утекает в публичные `/api/people`, IP только в
  журнале входов (доступен manager+), EXIF - постеры идут через `probe::square_image`/
  `images` (перекодирование - EXIF теряется, проверить на практике в тесте).

## 6. Поиск: опечатки, раскладка, транслитерация

Сейчас `catalog.rs::list` - подстрока после `norm` (регистр, ё); `/search` -
локальная выдача + `/api/discover/search` (IMDb/Wikipedia).

Решение (сервер, без новых зависимостей):
- Нормализация запроса `norm` + генерация **вариантов**:
  - раскладка ru↔en (`йцукен` ↔ `qwerty` map для букв, что совпадают по смыслу ввода);
  - транслитерация запроса в латиницу и обратно (простая таблица, не `names::translit`
    - он для имён; сделаем `util::translit_query` в обе стороны с 'е/э','и/й' вариантами);
  - опечатки: для локальной библиотеки - **prefilter по первым буквам + Levenshtein
    ≤1 на слово** только если точных результатов 0 или <3 (библиотека ≤ нескольких
    тысяч карточек - в памяти, быстро); для `/api/discover/search` - варианты запроса
    к IMDb только когда основной пуст (не спамим внешние API).
- Подсказки на лету: `GET /api/search/suggest?q=` - debounce 150 мс на клиенте,
  источники: локальная библиотека (top-5 по подстроке), недавние запросы
  (`localStorage`, до 8), «вы имели в виду?» при опечатке.
- Пустые/ошибочные состояния: «Ничего не нашлось - попробуйте „Начало“ без года»,
  кнопки «Сбросить фильтры», «Искать в интернете» (discover).
- Замер: `web/scripts/search-time.mjs` - это про видео-ссылки; для каталога добавить
  `search-time` сценарий в `perf.mjs` (уже есть `/search?q=гарри`).
