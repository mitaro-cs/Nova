# Новый плеер - план работ

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** заменить `web/src/lib/player/Player.svelte` (1919 строк) набором небольших модулей и новым интерфейсом (вариант C): предсказуемый выбор режима, автоматический переход на следующий вариант при сбое, лечение зависаний качеством, журнал событий; ничего из прежних возможностей не теряется.

**Architecture:** чистая функция `buildChain` строит цепочку режимов `raw -> remux|copy -> hls` по данным файла, возможностям браузера и настройкам; конечный автомат `PlaySession` ведёт цепочку (таймауты старта и зависания, переход к следующему варианту с того же места); движки (`native`, `hls`, `link`) только запускают поток; отдельные модули - дорожки, прогресс, пропуски, совместный просмотр, журнал; интерфейс - оболочка и небольшие компоненты. Новый плеер строится рядом со старым и подключается к страницам в конце; старый удаляется после проверки на равенство возможностей.

**Tech Stack:** SvelteKit 5 (руны), TypeScript, `hls.js/light` (лениво), Vitest (в том числе с поддельным `<video>` и поддельными часами), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-01-player-design.md`. Зависит от плана надёжности (`2026-11-01-reliability.md`, Task 3: `lib/diag.ts` и `POST /api/diag/client`).

## Global Constraints

- Всё по-русски, обычный дефис « - », без длинных тире; зрителям - «администрация/сервер Nova».
- Внутренние имена (`fsfy`, `X-Fsfy`) не менять; серверные потоки (`stream.rs`, `hls.rs`, `copy.rs`) не переписывать.
- Правила платформ: `copy` («Оригинал» HLS) только где HLS родной (Safari, WebKit); Windows/WebView2/Chromium - `remux`, затем `hls`. Не возвращать потоковую перепаковку в Safari (Range, новый ffmpeg на запрос).
- `hls.js` - только `hls.js/light` и лениво (для видео по ссылке с отдельными звуковыми дорожками - полная сборка, как сейчас); бюджет JS главной (`e2e/speed.spec.ts`, 80 КБ) не должен вырасти.
- Дизайн: вариант C (крупные центральные кнопки), Inter, токены `app.css`, движение только `opacity`/`transform`, стекло `backdrop-filter` только на маленьких капсулах; `confirm()/alert()` нельзя; Esc - как сейчас (меню, иначе назад к фильму; `+layout` всегда `preventDefault`).
- Пороги: старт без первого кадра - 8 с, ожидание посреди фильма - 3 с (константы в `plan.ts`).
- Имена файлов не совпадают без учёта регистра (`web/src/lib/paths.test.ts`).
- Проверки: `npm run check`, `npm test`, `npm run build`, `cargo build --release -p fsfy-server`, `npx playwright test --project=desktop --project=phone --project=tablet` с `FSFY_BIN=C:\Maison\Nova\target\release\fsfy.exe`; серверный код не меняется - `cargo test` достаточно один раз в конце.
- Коммиты - Conventional Commits, автор `Claude` через `-c user.name=Claude -c user.email=noreply@anthropic.com`, только локально; push, сборка и установка - по слову владельца.

## Review Focus

- Файл без `hls` на сервере (нет ffmpeg): цепочка из одного варианта, ошибка понятная («Этот файл нельзя воспроизвести в браузере - скачайте»), а не бесконечная загрузка.
- Перемотка в момент переключения режима не теряет место и не запускает два потока сразу.
- Быстрая смена серии/источника: поздний ответ старого потока не влияет на новый (поколение загрузки).
- `waiting` из-за перемотки (а не сети) не считается зависанием и не снижает качество.
- Закрытие страницы во время просмотра сохраняет место (`keepalive`), на другом устройстве продолжение с того же места.
- Видео по ссылке (Rutube, VK, свой сайт, YouTube не входит - свой плеер): прежние возможности качества и «Это не тот фильм».

## Что должно остаться (перечень равенства возможностей)

Режимы raw/remux/copy/hls; дорожки звука; субтитры WebVTT (cp1251) с настройкой вида; качество (оригинал, авто, высота) и замер скорости; скорость 0,25-2×; кадры перемотки; пропуск заставки и титров; следующая серия с отсчётом; список серий; видео по ссылке и смена источника (озвучка, «Это не тот фильм»); «Смотреть вместе» (`sync`); продолжение с места, «смотрите на другом устройстве»; проверка «длительность не совпадает»; PiP, полный экран, двойное касание, клавиатура; отчёт `net` в «Сейчас смотрят»; обратный отсчёт и «Далее»; отключаемый звук браузером (`mutedByBrowser`).
