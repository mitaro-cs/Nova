# Лабораторная: HTTP 401 и 403

Лаборатория запускается только на `127.0.0.1` и не обращается к внешним сайтам. Она помогает увидеть разницу между доступным ресурсом, отсутствующей аутентификацией и прямым отказом политики. В браузерной панели можно также показать, что подмена `User-Agent`, поддельный `X-Forwarded-For` и повторы не снимают 403.

## Запуск

Из корня репозитория:

```powershell
node docs/http403_lab.mjs
```

Открой `http://127.0.0.1:8765` в браузере и используй кнопки демонстрации. Либо проверь ответы из другого окна PowerShell:

```powershell
curl.exe -i http://127.0.0.1:8765/health
curl.exe -i http://127.0.0.1:8765/public
curl.exe -i http://127.0.0.1:8765/protected
curl.exe -i -H "Authorization: Bearer student-demo-token" http://127.0.0.1:8765/protected
curl.exe -i http://127.0.0.1:8765/forbidden
curl.exe -i -A "Browser/999.0" http://127.0.0.1:8765/forbidden
curl.exe -i -H "X-Forwarded-For: 203.0.113.42" http://127.0.0.1:8765/forbidden
```

Ожидаемые статусы: `/health` и `/public` — 200; `/protected` без токена — 401, с учебным токеном — 200; `/forbidden` — 403 даже при подменённых заголовках и повторе запроса. Сервер привязан только к loopback. Можно задать свой учебный токен переменной `NOVA_LAB_TOKEN` до запуска.

## Как разбирать 403 в разрешённой интеграции

1. Зафиксировать адрес, время, HTTP-статус, заголовки ответа и сетевой маршрут. Отдельно проверить, доступен ли домен и не является ли ошибка браузерным CORS-сообщением.
2. У 401 запросить ожидаемый способ аутентификации и передавать выданные учётные данные через предусмотренный канал.
3. У 403 запросить у владельца ресурса причину отказа, документированный API или embed, разрешение исходящего IP сервера и нужный scope/роль.
4. После официального разрешения повторить тот же запрос и сравнить ответы. Не подменять идентичность клиента, не обходить проверку доступа и не перебирать адреса.
5. Если владелец не предоставляет разрешённый интерфейс, пометить источник как недоступный для серверной интеграции. Для собственного контента использовать прямой HLS/DASH/файл или собственный API.

403 нельзя надёжно устранить универсальным заголовком или ретраями: решение зависит от политики владельца ресурса. В Nova проверка источника показывает отказ и следующий официальный шаг; она не обещает доступ к произвольному сайту.
